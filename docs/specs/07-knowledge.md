# 07: Knowledge for agents (and humans)

Data files shipped inside the binary (`include_str!`), under `crates/keyloom/data/`, versioned and tested.

## Keycode reference (`keycodes.json`)

One entry per keycode Oryx can produce, plus the whole-key forms keyloom writes (`LT`, `MT`, `TAP_HOLD`,
flagged `family`):

```json
{ "code": "KC_ESCAPE", "aliases": ["KC_ESC", "Esc", "Escape"], "category": "basic",
  "description": "Escape", "legend": "Esc", "verified": true }
```

Categories: basic, modifier, navigation, editing, function, numpad, media, system, mouse, layer,
mod-tap, one-shot, rgb, zsa, quantum, misc. `verified: true` marks codes seen in a real Oryx layout (the
fixtures); the others follow QMK and Oryx's naming pattern but are unconfirmed. Open: `TT`'s tap count in
Oryx; `KC_MEH`/`KC_HYPR` are aliases of the `MEH_T`/`ALL_T` hold actions (Oryx only showed those).
Source: QMK's keycode definitions (`data/constants/keycodes/*.hjson` in QMK) filtered to what Oryx offers
(from the encoding notes), plus aliases from `labels`. Generated by `crates/keyloom/tools/gen_keycodes.py` (offline table),
committed, regenerated on demand.

Used by `find` (alias normalisation), the action-spec parser, `unknown-keycode`, `lookup_keycode`.

## Positions, fingers and effort

Not a data file: `positions.rs` builds the Voyager's 52 positions with name (01), half, row, column, finger
(`pinky|ring|middle|index|thumb`), `effort` 0–1 and `home`. Effort, first version (hand-tuned): index home 0,
middle 0.05, inner index 0.15, ring 0.2, pinky 0.3, outer pinky column 0.55; top row +0.15, bottom row +0.2,
number row +0.4; thumb 1 0.05, thumb 2 0.15. Used to sort `free_keys` and by the design guides.
Other geometries (Moonlander) need their own table; until then their keys are named `#index`.

## Guides (`guides/*.md`)

Short, opinionated, written for an agent that will act on them. Each ends with a checklist.

- `layer-design.md`: when to use MO vs LT vs TG vs TO vs TT vs OSL vs DF; always have a way back;
  put layer keys on thumbs; keep transparent keys where the base layer should still work.
- `gaming.md`: plain keys only (no hold/tapHold/doubleTap: tap-hold adds delay and misfires under fast
  input); no home-row mods on or below the layer; movement cluster (WASD or ESDF) with abilities around it;
  modifiers (Shift/Ctrl/Alt) on thumbs for combinations; enter with `TG`/`TO`, leave with the same key on
  the gaming layer; keep Esc and Enter (chat) reachable; mention that games read key codes, not legends.
- `mmo.md` (WoW and similar): many binds → number row + keys around WASD for bars 1–12, modifiers
  on thumbs for bar pages, push-to-talk and target/interact keys near the movement cluster, mouse-hand
  side mostly free; ask how many bars and whether the right half is used at all.
- `nav.md`, `symbols.md`, `numbers.md` (numpad vs number row), `mouse.md` (incl. Navigator trackball
  auto-mouse layer), `home-row-mods.md` (timing trade-offs, per-layer disabling).

Guides are reviewed by hand; they're the main lever on agent quality and should be tested with real agent sessions.
